**拍转编完整面试故事(2026-07 定稿,约 90 秒口述版)**:
> **S**:TikTok 特效有两个入口:拍摄页和编辑页。我在创作工具团队时,部门有个 P0 级的策略项目"拍摄特效转编辑特效"——把拍摄页的存量特效搬到编辑页。我作为实习生被委任为这个项目的负责人。
> **T**:项目的起点是一个所有人都看得到、但没人能解释的现象:编辑页的特效供给量特别少——消费侧的需求(投稿占比)是供给占比的近 10 倍。体感上更直观:测试美国用户打开编辑页,永远是那几个重复的旧特效,新的、热门的特效上不来。正式员工看到的只是这个结果,链路卡在哪没人说得清。
> **A**:我做了两层。第一层,把整条搬运链路拆开:数仓送审 → 过滤 → 测试 → 人审 → 上线,逐层量化通过率,再用倒推公式算出:要满足每日上线目标,顶层送审量需要放大到多少。第二层,深入内容池分析被过滤掉的到底是什么:拉出过滤失败原因的分布,发现占比最大的"开拍触发类"规则,把大量其实并不依赖拍摄触发的高热度特效——尤其是美颜美妆类——错误地挡在了门外。基于这两层分析,我重设了取数和过滤规则(保留被误判的高热品类、放开评估后安全的类别),推动测试阈值调整和人审人力扩容,还设计了编辑页 Trending/New tab 的下发逻辑,让新上的热门特效真正到达用户。
> **R**:日送审量提升了约 12 倍,过滤和测试通过率都大幅提升,编辑页终于能持续上新的、热门的特效——供给侧问题从本质上解决了。对我来说更大的收获是:在一个数仓、算法过滤、测试、人审多方协作的链路里,学会了用漏斗诊断定位问题、用数据说服各方改规则。
**追问弹药**:①怎么判断"误杀"→ 高热度 + 实际不依赖拍摄触发;当时靠提示语(Blink eyes 等)判断不精确,我提出改用道具包参数/业务标签,这是规则质量的迭代;②有没有副作用/风险 → 放开规则前逐类人工 review 过滤条件、测试阈值改动先评估稳定性影响;③国际化细节 → 全球 top4k 选品对小市场不公平(美国 trending 二十多条、巴西个位数),提出分国家拆分;④作为实习生怎么推动五方 → 逐项 owner + 排期表 + 用数据代替观点争论。**完整回答(30 秒版)**:"我的做法是把'该不该做'的立场之争,换成'数据说了什么、代价是什么'的事实之争。两个例子:过滤方担心放开规则影响质量,我没有争'不会出问题',而是拉出过滤失败原因的分布,再对被误杀的高热特效逐类抽样人工 review,把问题从'放开安不安全'缩小到'这一类,review 过,安全'——分歧就消失了;上游觉得加送审量工作量大,我用倒推公式算给他们看每日上线目标反推的送审需求,再拆成分阶段方案和每层的开发人天,把'要不要做'变成'按什么节奏做'。数据的作用不是压服对方,而是承接对方的顾虑——质量顾虑用抽样 review 承接,工作量顾虑用分阶段灰度承接。"
- 背景:拍转编搬运路径 **数仓送审 → Loki 过滤 → 测试 → 人审 → 上线**;80%+ 的特效被"开拍触发类"规则过滤,最终上线量仅剩个位数/极少
- 她的《拍转编审核策略优化》(2024-03,署名何贝尔):重设数仓与 Loki 过滤逻辑——数仓取数时去除不适合编辑页的开拍触发类但**保留被误判的美颜美妆类**(靠提示语 Blink eyes/Multi-faces/Show cat 等识别,并指出提示语判断不精确、建议改用道具包参数或 Loki 业务标签);搬运条件 7 天内投稿 top4k;设计 Trending Tab(与拍摄页共用推荐逻辑)与 New Tab(按人审上线顺序)下发逻辑

## Trust & Safety / 反欺诈弹药(来源:TikTok Shop Anti-fraud Solutions PM 面试逐字稿,2025-07,面试官 Mason;2026-08 归档)

> ⚠️ 以下数字均为本人面试中的 claim,无第三方验证;书面/口头使用保持同口径。

### 抖音探索页治理(完整版,比简历版细)
- 场景:抖音探索页图文瀑布流;低质封面 external PV **9%**,超 5% 阈值
- 动作:基于审核数据+互动信号设计低质识别规则;改规则+提模型效率+提人审效率
- 结果:external PV **9%→3.8%**;高风险内容 −12%;**CTR 波动上涨(counter metric)**;"tearful"类误伤 −78%(与积极词组合训练);每天减少 3,000+ 审核 case → 人审效率 +80%

### 法务 vs 运营 · 分层执法 STAR(policy communication 王牌)
- S:法务要求严规则过审,运营怕过度拦截伤用户体验
- A:分析近 3 个月违规数据 → **<20% 真高危,~80% 模糊词**(如抱怨客服态度)→ 提分层方案:**立即屏蔽词**(保合规)+ **待复审词**(二轮审核给缓冲)→ 单业务线 2 周试点,每天向双方同步拦截数据和用户反馈
- R:高危词拦截率近 100%(法务满意);用户投诉率 −20%(运营满意);全量后整体投诉 −15%
- 学习:分层方案让所有 stakeholder 都能接受;重视用户申诉与人审反馈

### 申诉与指标词汇(实战用过)
- 离线:precision / recall / F1;线上:FP 率 / FN 率;用户侧:**appeal rate / appeal win rate**、engagement(CTR 做 counter metric)
- 人审反馈闭环:审核员报误伤实例 → 组合正向词训练 → FP 下降

### 特效故事 · 反欺诈/误伤取景(同素材换皮)
- 漏斗整体转化率 **0.06%**;SQL 挖历史拒绝原因 → 过滤规则**系统性误杀**高热度有效内容(抠图/人脸分割/背景移除类)
- 四层修复:数仓选品规则(近7天top→不限发布时间)/ 平台过滤品类规则解封 / QA 放宽内存帧率限制 / 人审扩容+培训+看板(转化率、审核准确率);每天 6,000+ 新进人审
- 结果:日可用特效 <10 → 4,000+(=400x 口径的出处)

### 信用卡反欺诈 ML 项目(学校,Kaggle 数据集)
- 数据:120 万交易,仅 **0.58%** 欺诈(极不平衡);15% 邮编缺失(众数填补)、one-hot 编码
- 特征工程:交易小时、周末 flag、线上交易指示符
- 方法:XGBoost / Random Forest / Logistic / KNN 对比;**SMOTE + ADASYN** 处理不平衡;超参调优
- 结果:recall 与 F1 显著提升;XGBoost+ADASYN 最优
- ⚠️ 口径:offline 数据集、train/test 划分;别说成线上系统
