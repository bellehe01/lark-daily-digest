> 情报依据:一面/二面以 **BQ + 场景题**为主,结合简历深挖;HM 最关心
> "遇到一个用户问题,你怎么定位、怎么排查、什么时候升级给工程、怎么领导推动问题解决"。
> 一面和 HR 面是中文,二面中英各半 —— 核心表达两种语言都过一遍。

## 零、万能骨架(任何场景题开口前默念)

```
① 澄清 Clarify → ② 报结构 Structure → ③ 分步展开 Execute
→ ④ 主动讲权衡 Trade-off → ⑤ 闭环 Close(跟进 + 预防)
```

- **第一句永远是澄清**:"我先确认几个信息:影响一个用户还是多个?有没有截止时间压力?"
  > EN: "Let me clarify the scope first — is this affecting one user or many, and is there a deadline at stake?"
- **第二句报框架**:"我会分四步:定位、止血、根因、沉淀。" —— HM 说的"逻辑清晰"就是这句。
- **最后一句永远是预防**:"事后我会评估这类问题能否自动化或写进 SOP。"

## 一、六类题型 × 框架 × 你的素材

### 1️⃣ 故障/工单处理题(主菜,必考)

**框架:范围 → 分层 → 止血 → 升级 → 根因 → 沉淀**

| 步骤 | 动作 | 关键话术 |
|---|---|---|
| 范围 | 一人/多人?一个功能/整站?何时开始? | "先判断是个例还是批量故障" |
| 分层 | Console 报错=前端;403=权限;5xx=后端;200 但数据错=数据层 | "用状态码把问题路由到对的层级" |
| 止血 | 先给 workaround,让用户能干活 | "先止血,再治根" |
| 升级 | 带复现步骤+请求证据+已排除项,给工程可直接行动的报告 | "升级不是甩锅,是带着证据交接" |
| 根因 | 跟进工程修复,确认用户侧真正解决 | "跟进到用户确认,不是工程说修了就完" |
| 沉淀 | SOP/FAQ/自动化,消灭这类工单 | "让下一个同类问题不再需要我" |

**素材**:SCF 工单事件(20+ 投诉→根因是人工流程→自动化根治)、日常 10-30 条/天的分诊流。

### 2️⃣ 优先级冲突题

**框架:全部先 ack → 影响面×紧急度排序 → 管理预期 → 复盘**

- 排序公式:阻塞人数 × 是否有 deadline × 有无 workaround
- 四象限口诀:高影响高紧急立刻做;高影响低紧急排期;低影响高紧急给 workaround;低影响低紧急合并批处理
- 别忘了"管理预期":没轮到的人要收到明确的预计时间

**素材**:活动现场同时爆多个问题时的取舍;日常多渠道咨询并发。

### 3️⃣ 流程改进题(第二爱考,对应 "review tickets for process enhancements")

**框架:量化现状 → 定位瓶颈 → 设计方案 → 小范围验证 → 推广 + SOP**

**素材**:weekly report(5/30 用户同类需求→自助编辑功能);AE 手动摘数(漏错频发→API 自动化,省 250h/月)。

### 4️⃣ 跨团队推动题(influence without authority)

**框架:量化影响 → 证据打包 → 找共同利益 → 拿到时间承诺 → 到点跟进/升级**

- 量化:"这个 bug 每天阻塞 30 个 AM 共 15 小时"比"很多人受影响"有力十倍
- 降低对方成本:复现步骤、请求日志、影响清单全部打包好
- 共同利益:"这个数据错误也在污染你们的模型输入"
- 承诺:"能给我一个预计修复时间吗?我好同步给用户" —— 软但有效
- 不动:升级到双方 manager 对齐优先级,同时继续手动 workaround

**素材**:与工程重构 ETL 数据流(400x)的协作;推动工具修复的日常。

### 5️⃣ 指标异动题("某类工单突然翻倍")

**框架:先证真 → 再拆解 → 后归因 → 给行动**

- 证真:埋点/管道/统计口径先排除(你的 SSOT 自带 QA 校验,这步你天天做)
- 拆解:按时间/地区/用户类型/类别切片,找异常集中在哪
- 归因:内因(发版?改流程?)vs 外因(活动?周期?)
- 行动:短期应对 + 长期修复

### 6️⃣ 模糊需求题("用户说工具不好用")

**框架:5W 追问 → 复现 → 区分表面问题和真问题 → 分类处理**

- "不好用"三种可能:bug(走工单)、不会用(补文档/培训)、需求缺失(进产品 backlog)
- **素材**:weekly report 案例——用户表达的是"格式不对",真需求是"自助定制"。

## 二、追问闭环两技巧(HM 认可 Wäger 的正是这个)

1. **每步备 Plan B**:被追问"如果这招不行呢?"时——
   - 用户联系不上 → 查日志自己复现
   - 工程说下周才修 → 手动 workaround + 广播受影响用户 + 记入已知问题
   - 无法复现 → 找用户要录屏/HAR,约时间远程看
2. **结尾回到预防**:任何题最后落在"自动化/SOP/推产品修复"——呼应简历第二主题,让面试官觉得简历和人是一致的。

## 三、模拟题库(每类 2 题,mock 时用)

**故障处理**
1. 一个运营同学说"看板上今天的 GMV 数据是空的",马上要给客户汇报。你怎么办?
2. 早上开班你发现工单队列里积压了 40 张未处理的 ticket(平时只有 10 张),怎么处理?

**优先级**
3. 同时收到:①大客户的报表打不开(1 人);②内部工具登录失败(20 人);③一个 creator 投诉 tier 错误(1 人,情绪激动)。怎么排?
4. 你正在处理一个复杂问题,manager 又转来一个"高优"新问题,怎么办?

**流程改进**
5. 你发现每周都有 5-6 张关于"权限申请"的工单,内容几乎一样。怎么办?
6. 交接班时经常出现信息丢失,前一班处理到一半的问题下一班不知道。你怎么改进?

**跨团队推动**
7. 你升级了一个 bug,工程说"两周后才有空看",但用户每天都在被阻塞。怎么办?
8. 你想推一个自动化方案替代手动流程,但流程 owner 觉得"现在这样也挺好"。怎么推?

**指标异动**
9. "工具报错"类工单这周环比涨了 3 倍,你怎么分析?
10. CSAT(用户满意度)连续两周下滑,怎么查?

**模糊需求**
11. 一位高管说"这个报表看着不舒服",没有更多信息。怎么办?
12. 用户要求给工具加一个功能,但你觉得已有功能能满足。怎么回应?

## 四、BQ 快查表(STAR 法,配好你的故事)

| 高频 BQ | 用哪个故事 | Result 收尾句 |
|---|---|---|
| 讲一次你解决复杂问题的经历 | SCF 工单事件 | 工单类别消灭,4h→20min |
| 讲一次你主动改进流程的经历 | 250h API 自动化 | 消灭一整类数据错误 |
| 讲一次你处理高压/紧急情况 | 活动现场实时支持 | 5,000 人活动零重大事故 |
| 讲一次跨团队协作/推动别人 | ETL 重构(和工程) | 吞吐 400x |
| 讲一次从用户反馈到行动 | weekly report 自助编辑 | 该类请求归零 |
| 讲一次失败/做得不好的经历 | (需要你自己定,建议选"低估了某流程的人工成本,后来用自动化补救"方向) | 学到:先量化再动手 |
| 为什么想来这个岗位/TikTok | 平台侧+代理侧双视角 + 想回字节生态 | — |

**STAR 时间配比**:S+T 共 20%,A 占 60%(面试官要听的是"你"做了什么,用"我"不用"我们"),R 占 20%(数字收尾 + 一句 takeaway)。
